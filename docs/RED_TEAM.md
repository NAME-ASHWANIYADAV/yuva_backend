# Red-team review and fixes

Six lenses were applied to the prototype before it was declared finished. Each row is an attack, what we found when we checked, and what was changed (or why not).

| Lens | Attack | Finding | Fix / status |
|---|---|---|---|
| Power-systems engineer | "Your feeder model is lumped; no voltage, no power flow." | True. Loads aggregate radially DT → feeder → PT; no AC power flow. | Stated as a limitation in README/CLAIMS. Power flow adds no information to the switching decision at this stage; it would matter for a voltage-quality co-benefit, which we do not claim. |
| Power-systems engineer | "At full participation three 8-hour spells on PT-2 cannot fit in a 10-hour window; your optimiser would be infeasible every day." | Correct at participation 1.0 (PT-2 load 5,289 kVA > 5,000): one contiguous spell per feeder is infeasible, and the published timetable overloads PT-2 (106 %). | Planning and verification use an ASSUMED P90 participation of 0.9 (4,760 kVA). At 1.0 the ladder finds a split-spell plan with night compensation (CERTIFIED_WITH_RELAXATION) and says so; import is about equal to the timetable's because night hours are counted as import. The calibration is documented in `configs/lamjana.yaml`. |
| Power-systems engineer | "Your verifier softened my full-participation scenario back to 0.9." | True in the first version: the verifier's P90 default overrode the scenario's declared participation. | The more pessimistic of the two now applies (`truth_engine.simulate`). |
| Power-systems engineer | "Linearising IEC 60076-7 inside a MILP is an approximation you must defend." | Not an approximation here: with three load states per block the forcing terms are constants, so the recursion is exactly linear in the on/off sequence. | Property test `test_linear_recursion_equals_nonlinear_for_two_state_load` (max abs. error < 1e-9). The optimiser now evaluates that recursion per candidate daily pattern (a DT's temperature depends only on its own feeder); the verifier still uses the nonlinear model. |
| Optimisation specialist | "Your u[f,t] MILP with thermal state variables has no incumbent after 30 s on split-spell days; the demo button stalls." | True: HiGHS timed out without a feasible point on 'everyone switches on' and the first feasible point on other days arrived after 15–30 s. | Column formulation (one binary per admissible daily pattern, per-feeder rules and the hot-spot filter moved into enumeration), PT cover cuts, and a seeded coordinate-descent heuristic that hands HiGHS a feasible start in < 0.5 s. Nominal days < 1 s; split rungs 9–18 s with the gap reported. |
| Optimisation specialist | "Do you trust the solver's 'infeasible'?" | Not blindly: HiGHS 1.15.1 presolve declared a nominal model infeasible that solves to optimality with presolve off and from an LP file. | Every infeasibility verdict is re-run with presolve off before the ladder moves on (`solver.py`). |
| Optimisation specialist | "The pattern lattice restricts optimality." | Yes: two-spell patterns with night compensation use a 30-min lattice and, by default, only the 2 h cap; the feasibility rung enumerates every value. | Stated in CLAIMS as a limitation on optimality, not feasibility. |
| Power-systems engineer | "Night compensation of 15 minutes is operationally meaningless." | The first version let the solver shave one block and 'compensate' it at night. | Night compensation is now an integer ≥ 4 blocks (1 h) when used, carries its full energy cost plus a penalty, and the ladder prefers a split spell over night compensation. |
| Power-systems engineer | "Tightening the margin cannot fix an infeasible day." | Correct; the first ladder did that. | Ladder now relaxes only what the circular allows (split spells, night compensation, deferred irrigation) when infeasible, and tightens only on verifier mismatch. Temperature limit, PT rating, cap and window are never relaxed. |
| ML researcher | "You trained a model on your own simulator." | No: the only learned component is trained on archived public NWP vs ERA5/NASA POWER; the simulator never produces training targets. | `DATA_SOURCES.md`, `features.py`; the `best_match` leakage path is refused in code. |
| ML researcher | "Your quantile model is under-dispersed." | First run: 80 % interval coverage 0.55. | Blocked (by month) split-conformal offsets from out-of-fold residuals → coverage 0.75 on the 2025 test year; pinball 21.8 vs 23.5 (linear). Shipping rule is pre-registered in code. |
| ML researcher | "ERA5 is not ground truth." | Correct. | Stated everywhere; NASA POWER used as a second proxy and the proxy-disagreement floor is reported. |
| ML researcher | "Lead-time evaluation?" | Only the day-1 lag archive is available; hour-of-day is used as the lead proxy. | Stated in `results/forecast/SUMMARY.md`. |
| DISCOM engineer | "Operators will not switch three times a day." | Default is one contiguous spell; split spells are an explicit relaxation flagged in the status and alert. | Ladder order and `CERTIFIED_WITH_RELAXATION` status. |
| DISCOM engineer | "Where does irrigation urgency come from in my control room?" | From a FAO-56 model on public weather and an assumed crop calendar; a DISCOM would take it from the agriculture department. | Labelled MODELLED/ASSUMED on the irrigation panel. |
| DISCOM engineer | "Does the plan ever violate the 8-hour rule?" | Hours are an equality (8 h) with the circular's night-compensation clause only; verified independently. | Pattern enumeration (`patterns.py`), verifier `supply_hours` check. |
| DISCOM engineer | "A plan with night compensation showed lower import than my timetable. That is a trick." | It was: night hours were not simulated, so their energy was missing from the import metric. | Night-compensation energy is now counted as 100 % grid import in every metric and in the baseline guard; the guard issues the published timetable unchanged when it verifies and is not more expensive. |
| Agronomist | "All feeders kharif-only; rabi season shows zero demand." | True in the first version. | Crop rotation added: Jawali soybean → chana, Chalburga soybean → wheat; cotton and tur run into December; buckets per crop; the in-season crop sets the requirement. |
| Agronomist | "Requirement toggled 32/0 blocks day to day." | The RAW threshold trigger was binary. | Requirement is now the water needed to keep depletion at RAW after today's crop use (continuous), capped by the 8-hour rule. |
| Agronomist | "Do you claim water savings?" | No. | Explicit on the irrigation panel, README and CLAIMS. |
| Hackathon judge | "Buttons take 30 s; the demo stalls." | With the first formulation, yes. | Column formulation + heuristic warm start: nominal certifications < 1 s, feeder outage ≈ 9 s, everyone-switches-on ≈ 18 s, impossible case ≈ 17 s incl. attribution. Named scenarios are also precomputed at backend start (real computations, cached; the log says 'cached' with the original time). |
| Hackathon judge | "Is the demo real or a video?" | Every button calls the backend; the ladder table shows real solve times. | — |
| Hackathon judge | "Which numbers are real?" | Weather, forecasts and rules; everything about the feeder is modelled. | Honesty footer on every screen; tags on every panel. |
| Startup engineer | "Where is persistence, auth, multi-site?" | Out of scope for a prototype; in-memory state, CORS open for development. | Stated in README. |
| Startup engineer | "Is the fallback real or a sentence?" | Real: injected solver failure and an impossible scenario both return the published timetable with an alert. | `test_certify_falls_back_on_solver_error`, `test_impossible_is_reported_not_faked`. |
| All | "Does it solve Agriculture or is it a grid project?" | The decision is when farm pumps run; the deadline and urgency are agronomic; the per-hectare metric is grid import per irrigated hectare; the farmer-facing output is a predictable daytime slot in Marathi. Grid benefits are co-benefits. | Metrics strip and messages. |

Open items we did not fix (and say so): plant-level forecast error is not learned separately (GHI quantiles pass through the PV model); the switching-cap share and start-separation rule are assumptions on top of the state-wide 50 MW rule; the FAO-56 model is single-Kc; no PT thermal model (rating only).
